# 部门管理系统 - 产品需求规格说明书

## 1. 项目概述

### 1.1 项目背景
构建一套基于 Web 的部门管理系统，实现组织信息维护、员工数据管理、考勤打卡和请假审批的数字化管理。

### 1.2 目标用户
| 角色 | 描述 |
|------|------|
| 管理员 | 统一管理所有部门和员工，处理审批事务 |
| 普通员工 | 日常打卡、查看个人信息、提交请假/补卡申请 |

### 1.3 规模预估
- 预计员工数量：50人以下
- 系统定位：轻量级内部管理系统

---

## 2. 组织架构管理

### 2.1 组织层级
- **层级结构**：公司 → 部门（两级）
- **员工归属**：每个员工只能属于一个部门

### 2.2 部门管理（管理员）
管理员可以对部门进行完整的增删改操作：

| 操作 | 说明 |
|------|------|
| 新增部门 | 输入部门名称，创建新部门 |
| 修改部门 | 修改部门名称 |
| 删除部门 | 删除部门（需处理部门下员工） |

**业务规则**：
- 删除部门时，需先将该部门下所有员工转移到其他部门，或标记离职
- 部门名称不可重复

### 2.3 职位管理（管理员）
管理员可以对职位进行完整的增删改操作：

| 操作 | 说明 |
|------|------|
| 新增职位 | 输入职位名称，创建新职位 |
| 修改职位 | 修改职位名称 |
| 删除职位 | 删除职位（需处理使用该职位的员工） |

**业务规则**：
- 删除职位时，需先将使用该职位的员工修改为其他职位
- 职位名称不可重复
- 添加/编辑员工时，职位只能从已有职位列表中选择（下拉框）

## 3. 员工管理

### 3.1 员工信息字段

| 字段 | 说明 | 必填 |
|------|------|------|
| 工号 | 唯一标识，系统生成或手动输入 | 是 |
| 姓名 | 员工真实姓名 | 是 |
| 手机号 | 联系电话 | 是 |
| 邮箱 | 电子邮箱 | 否 |
| 入职日期 | 入职时间 | 是 |
| 职位 | 岗位名称 | 是 |
| 所属部门 | 关联部门 | 是 |
| 账号 | 登录账号 | 是 |
| 密码 | 登录密码 | 是 |

### 3.2 员工管理功能（管理员）

| 功能 | 说明 |
|------|------|
| 新增员工 | 录入员工信息，创建登录账号 |
| 编辑员工 | 修改员工信息（工号不可改） |
| 离职处理 | 标记员工为离职状态，保留历史数据 |
| 查询员工 | 按姓名、工号、部门筛选 |

**业务规则**：
- 工号全局唯一，不可修改
- 离职员工不可再进行打卡、请假等操作
- 离职员工的历史考勤、请假记录保留可查
- 登录账号全局唯一

### 3.3 员工自助（普通员工）

| 功能 | 说明 |
|------|------|
| 查看个人信息 | 查看自己的基本信息（只读） |
| 修改密码 | 修改自己的登录密码 |

## 4. 考勤打卡

### 4.1 班制设置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 上班时间 | 09:00 | 管理员可修改 |
| 下班时间 | 18:00 | 管理员可修改 |
| 打卡地点限制 | 无限制 | 不限制打卡地点 |

### 4.2 打卡功能（员工）

**操作流程**：
1. 员工登录系统
2. 点击「上班打卡」或「下班打卡」
3. 系统记录打卡时间
4. 显示打卡结果（正常/迟到/早退）

**业务规则**：
- 每天只能打一次上班卡、一次下班卡
- 上班时间后打卡 → 标记为「迟到」
- 下班时间前打卡 → 标记为「早退」
- 不限制打卡地点
- 离职员工不可打卡

### 4.3 补卡申请（员工）

**触发场景**：员工忘记打卡时使用

**操作流程**：
1. 员工选择补卡日期和时段（上班/下班）
2. 填写补卡原因
3. 提交申请，等待管理员审批

**业务规则**：
- 只能补过去7天内的打卡记录
- 每天每个时段只能补卡一次
- 补卡审批通过后，覆盖原始打卡记录

### 4.4 考勤统计

**查看范围**（管理员）：
- 可查看所有员工的考勤记录
- 按月份、部门、员工筛选
- 显示统计：应出勤天数、实出勤天数、迟到次数、早退次数、请假天数

**查看范围**（员工）：
- 只能查看自己的考勤记录
- 按月份查看
- 显示个人统计

### 4.5 员工首页打卡历史（员工）

员工首页展示近期打卡历史记录：

| 内容 | 说明 |
|------|------|
| 今日打卡状态 | 显示今日上班/下班打卡时间和状态 |
| 本月考勤统计 | 正常天数、迟到次数、早退次数 |
| 打卡历史列表 | 最近 7 天的打卡记录（日期、上班时间、下班时间、状态） |

## 5. 请假管理

### 5.1 假期类型

| 类型 | 说明 |
|------|------|
| 事假 | 个人事务请假 |
| 病假 | 因病休息 |

### 5.2 请假申请（员工）

**必填信息**：
- 假期类型（事假/病假）
- 开始日期
- 结束日期
- 请假事由

**操作流程**：
1. 员工填写请假信息
2. 提交申请
3. 等待管理员审批
4. 系统内收到审批结果通知

**业务规则**：
- 结束日期不得早于开始日期
- 同一时间段内不可重复请假
- 审批中的申请不可重复提交

### 5.3 请假审批（管理员）

**操作流程**：
1. 查看待审批列表
2. 查看请假详情
3. 选择「通过」或「驳回」
4. 驳回时需填写驳回原因
5. 系统通知员工审批结果

**业务规则**：
- 通过后自动统计到考勤记录中
- 驳回后员工可重新提交

## 6. 系统通知

### 6.1 通知类型

| 触发场景 | 通知对象 | 通知内容 |
|----------|----------|----------|
| 请假申请提交 | 管理员 | 收到新的请假申请 |
| 请假审批通过 | 员工 | 请假已通过 |
| 请假审批驳回 | 员工 | 请假已驳回（含原因） |
| 补卡申请提交 | 管理员 | 收到新的补卡申请 |
| 补卡审批通过 | 员工 | 补卡已通过 |
| 补卡审批驳回 | 员工 | 补卡已驳回（含原因） |

### 6.2 通知展示
- 系统顶部显示未读通知数量
- 点击进入通知列表
- 通知标记已读/未读

## 7. 系统管理

### 7.1 账号与登录

| 项目 | 说明 |
|------|------|
| 登录方式 | 账号 + 密码 |
| 管理员账号 | 系统预置，不可删除 |
| 密码修改 | 员工可修改自己的密码 |
| 密码重置 | 管理员可重置员工密码 |

### 7.2 数据安全
- 密码加密存储
- 员工只能访问自己的数据
- 管理员可访问所有数据

## 8. 功能边界（V1 不包含）

以下功能在第一版本中**不实现**：

- 年假管理及额度计算
- 跨天请假（简化为按天请假）
- 半天假、小时假
- 法定节假日自动处理
- 邮件/短信通知
- 考勤报表导出（Excel等）
- 手机验证码登录
- 外勤打卡、地理位置定位
- 员工自助删除账号
- 多级审批流程
- 薪资管理
- 员工照片/头像管理

## 9. 用户故事摘要

### 管理员视角
1. 作为管理员，我可以新增/编辑/删除部门，以便维护组织架构
2. 作为管理员，我可以新增/编辑/删除职位，以便维护职位体系
3. 作为管理员，我可以新增/编辑员工信息，以便管理人事数据
4. 作为管理员，我可以将员工标记为离职，以便处理人员变动
5. 作为管理员，我可以修改班制时间，以便适应公司作息安排
6. 作为管理员，我可以审批请假申请，以便控制人员出勤
7. 作为管理员，我可以审批补卡申请，以便处理异常打卡
8. 作为管理员，我可以查看所有员工的考勤统计，以便掌握出勤情况
9. 作为管理员，我可以重置员工密码，以便处理账号问题

### 员工视角
1. 作为员工，我可以打卡记录上下班时间，以便证明我的出勤
2. 作为员工，我可以查看首页打卡历史，以便快速了解近期考勤情况
3. 作为员工，我可以查看自己的考勤记录，以便核对出勤情况
4. 作为员工，我可以提交请假申请，以便申请休假
5. 作为员工，我可以提交补卡申请，以便补录忘记的打卡
6. 作为员工，我可以查看个人信息，以便确认资料正确
7. 作为员工，我可以修改自己的密码，以便保障账号安全
8. 作为员工，我可以收到审批结果通知，以便了解申请状态

## 10. 验收标准

### 核心流程验收
1. **部门管理**：管理员可以成功新增、修改、删除部门
2. **员工管理**：管理员可以成功新增员工，员工可以用分配的账号登录
3. **打卡流程**：员工可以成功打卡，迟到/早退正确标记
4. **请假流程**：员工提交请假 → 管理员审批 → 员工收到通知 → 考勤统计正确更新
5. **补卡流程**：员工提交补卡 → 管理员审批 → 打卡记录正确更新
6. **权限隔离**：员工只能查看自己的数据，管理员可以查看所有数据

### 边界条件验收
1. 离职员工无法登录或打卡
2. 删除有员工的部门时提示先转移员工
3. 不可重复请假、重复打卡
4. 补卡只能补7天内的记录
